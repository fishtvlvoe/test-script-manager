   - 用於傳統 AJAX 請求失敗時

<task type="auto">
  <name>Task 2: Create CodeScanner class for dangerous function detection</name>
  <files>
    includes/class-code-scanner.php
  </files>
  <action>
建立 `includes/class-code-scanner.php`：

1. **私有常數：DANGEROUS_FUNCTIONS**
   陣列包含以下危險函數：
   - eval
   - exec
   - system
   - shell_exec
   - passthru
   - popen
   - proc_open
   - pcntl_exec
   - create_function（PHP 7.2 已棄用）

2. **靜態方法：scan(string $code): array**
   - 使用 token_get_all('<?php ' . $code) 解析 PHP 代碼
   - 遍歷 tokens，找出 T_STRING 類型且名稱在 DANGEROUS_FUNCTIONS 中的
   - 返回找到的危險函數陣列（去重複）
   - 例如：['eval', 'exec'] 或空陣列 []

3. **靜態方法：should_block_dangerous(): bool**
   - 返回 !(defined('WP_DEBUG') && WP_DEBUG)
   - true = 應該阻擋危險函數（生產環境）
   - false = 允許危險函數（開發環境）

4. **靜態方法：validate_code(string $code): array**
   - 整合 scan() 和 should_block_dangerous()
   - 返回格式：
     ```php
     [
         'valid' => bool,
         'dangerous_functions' => array,
         'message' => string|null
     ]
     ```
   - 如果 should_block_dangerous() 為 false，即使有危險函數也返回 valid = true
   - 如果 should_block_dangerous() 為 true 且發現危險函數，valid = false

為什麼使用 token_get_all 而非 regex：
- Regex 可能被繞過（例如：字串內的函數名稱、註解內的函數名稱）
- Tokenizer 準確解析 PHP 語法，只檢測實際的函數呼叫
  </action>

```bash

```

- 輸入 '// eval() is dangerous' 應該返回 []（註解不計算）
