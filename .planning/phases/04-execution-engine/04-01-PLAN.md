<objective>
Create the core execution service that runs PHP scripts with comprehensive output buffering, tri-layer error capture, and performance metrics.

Purpose: This is the heart of the execution engine. Users need to execute scripts and see all output (including errors) without crashing WordPress. The service must capture everything a script produces and measure its resource usage.

Output: Two service classes - ExecutionService for running scripts, OutputFormatter for detecting/formatting result types.

Note: Timeout is configurable per-execution via the $timeout parameter (1-300 seconds, default 30). User-facing timeout settings UI will be added in Phase 7 (Settings page). This satisfies SEC-04 at the API level.
</objective>

<task type="auto">
  <name>Task 1: Create ExecutionService with tri-layer error capture</name>
  <files>includes/services/class-execution-service.php, includes/services/class-script-service.php</files>
  <action>
Create ExecutionService class in TSM\Services namespace with these components:

**Constants:**
- MAX_OUTPUT_SIZE = 10 * 1024 * 1024 (10MB)
- MAX_TIMEOUT = 300 (seconds)
- DEFAULT_TIMEOUT = 30 (seconds)

**Static properties for error capture:**
- private static $captured_errors = []
- private static $captured_exception = null

**Main execute() method:**
1. Accept $script_id and optional $timeout (default DEFAULT_TIMEOUT)
2. Get script via ScriptService::get()
3. Get file path via StorageService::get_script_path()
4. Validate code via CodeScanner::validate_code() - return WP_Error if invalid
5. Store original timeout with ini_get('max_execution_time')
6. Set up tri-layer error capture:
   - set_error_handler() to capture warnings/notices
   - set_exception_handler() for uncaught exceptions
   - Try/catch with Throwable for caught exceptions
7. Track start metrics: microtime(true), memory_get_usage(true)
8. Set timeout with set_time_limit(min(max($timeout, 1), MAX_TIMEOUT))
9. Execute with ob_start() and include()
10. Capture output with ob_get_clean()
11. Restore handlers and timeout
12. Calculate metrics: execution_time, memory_usage (peak - start)
13. Truncate output if > MAX_OUTPUT_SIZE
14. Check for fatal error via error_get_last()
15. Update ScriptService::update_last_executed()
16. Log execution to database
17. Return result array with execution_id

**Result array structure:**
```php
[
    'output'         => string,
    'errors'         => array,    // [{type, level, message, file, line}, ...]
    'exception'      => array|null, // {type, message, file, line, trace}
    'fatal'          => array|null, // {type, message, file, line}
    'execution_time' => float,    // seconds
    'memory_usage'   => int,      // bytes
    'status'         => string,   // 'success', 'error', 'fatal_error'
    'execution_id'   => int,      // ID of logged execution record
]
```

**Error handler method:**
```php
public static function error_handler($errno, $errstr, $errfile, $errline) {
    self::$captured_errors[] = [
        'type'    => $errno,
        'level'   => self::error_level_name($errno),
        'message' => $errstr,
        'file'    => $errfile,
        'line'    => $errline,
    ];
    return true; // Don't execute PHP's default handler
}
```

**error_level_name() helper:**
Map E_ERROR, E_WARNING, E_PARSE, E_NOTICE, E_USER_ERROR, E_USER_WARNING, E_USER_NOTICE, E_STRICT, E_DEPRECATED, E_USER_DEPRECATED to readable names.

**log_execution() method:**
Insert to tsm_execution_logs table with:
- script_id
- output
- error (JSON encoded: {errors, exception, fatal})
- execution_time
- memory_usage
- status
- executed_at (current_time('mysql'))

Return $wpdb->insert_id (the execution_id).

**Also update ScriptService:**
Add update_last_executed($script_id) method that sets last_executed_at = now.

**Important safeguards:**
- Track buffer level with ob_get_level() before start
- Clean any extra buffers after execution: while (ob_get_level() > $original_level) ob_end_clean()
- Always restore handlers in finally-like pattern
- Reset static properties before execution

Use TSM namespace. Follow WordPress coding standards.

<task type="auto">
  <name>Task 2: Create OutputFormatter for result type detection</name>
  <files>includes/services/class-output-formatter.php</files>
  <action>
Create OutputFormatter class in TSM\Services namespace for detecting and formatting different output types.

**is_table_data($data) method:**
Detect if data is suitable for table display:
1. Must be array and not empty
2. First element must be array or object
3. All elements must have same keys (consistent structure)

Returns boolean.

**format_as_table($data) method:**
Convert array-of-arrays/objects to HTML table:
1. Extract headers from first row keys
2. Build HTML with classes for styling:
   - Wrapper: `<div class="tsm-table-wrapper">`
   - Table: `<table class="tsm-result-table">`
   - Headers: `<thead><tr><th>...</th></tr></thead>`
   - Rows: `<tbody><tr><td>...</td></tr></tbody>`
3. Use esc_html() for all content
4. Handle NULL, boolean, nested array/object in cells

**format_cell_value($value) helper:**
- NULL -> 'NULL'
- true/false -> 'true'/'false'
- array/object -> wp_json_encode()
- other -> (string) cast

**detect_output_type($output) method:**
Analyze output string and return type:
- 'json' if valid JSON (starts with { or [ and json_decode succeeds)
- 'table' if starts with '<table' or contains tabular markers
- 'html' if contains HTML tags
- 'text' for plain text

**format_memory($bytes) method:**
Human-readable memory format:
- Use size_format() WordPress function
- Example: 1048576 -> '1 MB'

**format_time($seconds) method:**
Human-readable time format:
- < 0.001: sprintf('%.4f ms', $seconds * 1000)
- < 1: sprintf('%.2f ms', $seconds * 1000)
- >= 1: sprintf('%.2f s', $seconds)

Use static methods (utility class pattern). Follow WordPress coding standards.
